Purpose and scope

Simulate a strategy on one OHLCV data frame with order and trade accounting, optimization, and performance statistics.

Design decisions

Decision Rationale Tradeoff Evidence
Process broker orders before each strategy callback. Orders submitted by the previous callback are evaluated on the next available bar. OHLC bars cannot uniquely reconstruct intrabar stop/limit ordering. Backtest.run (L1271) / Backtest.optimize (L1386) / _Broker.new_order (L765) / _Broker._process_orders (L875)

Strengths and limits

Strengths

  • Compact user strategy API with built-in optimization and statistics. Backtest.run (L1271) / Backtest.optimize (L1386) / Strategy.buy (L219) / Strategy.next (L200) / compute_stats (L37)

Limitations

  • The broker explicitly warns when contingent SL/TP execution is ambiguous within the entry bar. _Broker.new_order (L765) / _Broker._process_orders (L875)
  • The core Backtest consumes one price series frame and warns about prices above available cash and whole-unit trading. Backtest.run (L1271) / Backtest.optimize (L1386)
